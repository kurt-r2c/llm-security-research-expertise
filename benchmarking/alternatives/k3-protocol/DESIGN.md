# K3 Systematic search protocol

Mechanism: the note carries no vulnerability facts. It imposes a procedure borrowed from systematic-review and diagnostic-error practice: enumerate entries (E list) and sinks (S list) before judging anything, form (entry, sink) pairs, force an explicit disposition (VULNERABLE / SAFE / UNCERTAIN) per pair, and run a closing pre-mortem. A compact per-language grep catalogue seeds enumeration so Grep-only agents start from concrete patterns. Step 4 lists "control not actually enforced" shapes (result discarded, not awaited, wrong object, check before decoding, authn vs authz, sibling-handler diff). Stop rules counter premature closure: keep scanning a file after the first finding, one report per root cause.

Testable prediction: relative to vanilla, recall rises on bugs that are one-of-many (missing authz on one route among many, a sibling handler lacking a check, second-order or config-fed paths, a control present but ineffective). Recall should not improve on bugs needing domain knowledge the agent lacks (novel parser differentials, library-specific gadgets, subtle crypto), and not on bugs in code the greps do not surface (custom wrappers with unusual names). Precision should be flat to slightly better (the do-not-report block plus per-pair SAFE dispositions), with a risk of more low-value reports from forced pair coverage. Expected cost: higher, roughly 1.3-2x tool calls and output tokens, since the ledger and enumeration are mandatory; most extra spend is Grep and Read of callers. Small turn budgets may run out before the ledger closes.

Source guides: methodology/bug_hunting_first_principles_expertise.md (section 4(f) per-language grep-first, hotspot matrix, auth-homogeneity), methodology/code_review_expertise.md (authn-vs-authz, candidate-point auditing, resolve-then-verify path checks, JWT algorithm pinning, over-reliance-on-grep caveat), language-footguns (python, javascript_node, go, java, php, ruby) via the 4(f) summaries, vuln-classes (shell injection weak sanitizers, deserialization, SSRF) for the sink and control cues.

Strongest argument it fails: the earlier null result for the corpus may not be a search failure at all. If missed bugs are reasoning or knowledge failures (the agent reads the right code and misjudges it), enumeration just adds cost and noise. A long procedure at the top of the prompt can be skimmed or satisfied ceremonially (a ledger filled with shallow SAFE verdicts, which is premature closure with paperwork). Forced coverage also dilutes attention on the few high-yield paths, and the grep catalogue anchors the agent on classic injection sinks while logic and authorization bugs, the largest missed class, have no grep signature.
