K1 Checklist: design rationale

Mechanism. Gawande and Pronovost found that short, cue-triggered checklists prevent omission errors by experts who already know the material; they fix recall failure, not knowledge gaps. Sweller's cognitive load theory and Miller/Cowan working-memory limits (about 4 chunks) argue against 8.6MB of prose: reading a long guide spends context on extraneous load and dilutes attention. A 800-word note sits in the prompt as an external memory aid (cognitive offloading). Grouping by code-visible cue (decorator, call name, URL fetch) matches how an agent actually works with Grep: a cue is found, then the probes fire. Taxonomy chapters require the model to first decide which chapter applies. The do-not-report block is a precision brake.

Testable prediction. Improved: recall on omission-type bugs, meaning checks that exist but are not enforced (ignored result, unawaited async, wrong object checked), ownership/IDOR gaps, validator/fetcher parser differentials, JWT pin and verify flags, and TOCTOU on counters. Also fewer "forgot to grep X" misses per language. Not improved: bugs needing deep domain knowledge, multi-file data-flow reasoning, novel gadget chains, framework-specific semantics, or anything the model already checks unprompted. Precision should be flat to slightly up. If vanilla already runs these probes implicitly, the effect will be about zero.

Sources. software/methodology/bug_hunting_first_principles_expertise.md (per-language grep-first lists, injection lens), code_review_expertise.md (trust transitions, candidate points), appsec-web/distributed_authz_expertise.md (resource- vs operation-scoped authz, role-string compare, JWT footgun table, TOCTOU), vuln-classes/ssrf_url_parsing_expertise.md (userinfo/startswith/redirect_uri/scheme-relative), shell_injection, deserialization, template_code_injection, prototype_pollution, race_conditions, redos and xml_parser_differential guides, and crypto-trust/cryptography_expertise.md for the token probes.

Strongest argument for failure. The earlier result suggests the bottleneck is not knowledge access but search and verification depth. A frontier model already knows these probes; a list of 33 generic items adds no new information and may add distraction. Terse imperatives can also induce shallow pattern-matching: the agent greps every cue, over-reports sink hits without tracing, and spends its turn budget on breadth instead of the one deep cross-file flow where the real bug sits. The do-not-report block may suppress true findings that look like the listed traps (admin-only, config-fed). Compression discards the worked examples and gadget specifics that distinguish a real bug from a plausible one. Expect null or negative recall with a small precision gain.
