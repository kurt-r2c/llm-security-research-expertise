# K2 Contrast cases: design notes

Mechanism: the exposition-heavy guides are replaced by 28 minimal vulnerable/fixed pairs, indexed by the code shape a reader sees (an unused check result, a join feeding an open, a header-chosen algorithm) rather than by vulnerability class. Each pair carries a one-sentence invariant. The aim is analogical encoding and structure mapping: the agent compares the structure of the code in front of it with a stored contrast, and the invariant names the abstract rule that transfers across languages. Four decoys (looks vulnerable, is safe, with the reason) are included to teach the discriminating feature and to cut false positives. Worked examples replace prose, lowering extraneous load, and retrieval is cued by surface syntax the agent already has in context (encoding specificity).

Prediction (testable): with the same model and budget, agents given K2 will (a) open at least one case file in most runs because INDEX.md is short and grep-able, (b) rediscover shape-matching bugs (ignored guard results, unawaited async checks, two-object authorisation gaps, header-chosen algorithms) at a higher rate than vanilla, and (c) report fewer false positives on decoy-like code (shell with constant fragments, scoped finds, allow-listed identifiers). Expected gain is concentrated on bugs whose shape appears in the case set and near zero on logic bugs with no shape cue. If recall on shape-matched bug types is not above vanilla, the mechanism is not working.

Source guides used: vuln-classes (ssrf_url_parsing, shell_injection, prototype_pollution, race_conditions_concurrency, deserialization), appsec-web/session_management (token header attacks: alg, kid), crypto-trust/cryptography, appsec-web/distributed_authz. Snippets are synthetic and written fresh.

Strongest argument it fails: modern models already know every one of these patterns; the bottleneck in a real audit is reachability and tracing data flow through a large codebase, not recognising a textbook shape. Twenty-eight tiny textbook pairs add no information about that, and may add anchoring: an agent primed on canonical shapes may spend its budget grepping for them and report decoy-adjacent or textbook-looking code while missing the project-specific wrapper that hides the same flaw. The index grep cues are also surface-level, so they miss bugs that pass through helper functions.
